# Docker — Interview Questions & Answers

---

## Basics

**Q1. What is Docker?**
Docker is a platform that lets you build, ship, and run applications inside containers — lightweight, isolated environments that include everything the app needs to run.

**Q2. What problem does Docker solve?**
It solves the "it works on my machine" problem. Docker packages your app and all its dependencies together so it runs the same on any machine.

**Q3. What is a container?**
A container is a running, isolated process on your machine. It has its own filesystem, network, and processes but shares the host OS kernel.

**Q4. What is the difference between a container and a VM?**
A VM includes a full guest OS — heavy and slow to start. A container shares the host OS kernel — much lighter and starts in seconds.

**Q5. What is virtualization?**
Technology that lets you run multiple isolated computing environments on one physical machine by simulating hardware in software.

**Q6. What is Docker Engine?**
The core of Docker. It consists of the Docker CLI, Docker Daemon (`dockerd`), `containerd`, and `runc` — together they create and run containers.

**Q7. What is `dockerd`?**
The Docker Daemon — the main background process that receives commands from the CLI and manages images, containers, networks, and volumes.

**Q8. What is `containerd`?**
The container runtime that sits below the Docker daemon. It handles pulling images, managing storage, and the container lifecycle.

**Q9. What is `runc`?**
The lowest-level component that actually creates and starts containers by talking directly to the Linux kernel using namespaces and cgroups.

**Q10. What are Linux namespaces in Docker?**
Namespaces provide isolation. Each container gets its own PID, NET, MNT, UTS, and IPC namespaces so it cannot see other containers' processes or files.

**Q11. What are cgroups in Docker?**
Control groups (cgroups) limit how much CPU, RAM, disk I/O, and network bandwidth a container can use — preventing one container from consuming all resources.

**Q12. What does a stopped container use?**
Zero CPU and zero RAM. It only uses disk space to store the image layers.

**Q13. What is Docker Hub?**
The official default public registry made by Docker. It hosts official images like `nginx`, `postgres`, `node`, and community images.

**Q14. What is a Docker registry?**
A server that stores and distributes Docker images. Docker Hub is one registry, but others include AWS ECR, GitHub GHCR, and Google GCR.

**Q15. What is the difference between Docker Hub and a Docker registry?**
A registry is the concept — a server storing images. Docker Hub is one specific implementation made by Docker Inc. All Docker Hubs are registries but not all registries are Docker Hub.

## Images

**Q16. What is a Docker image?**
A read-only blueprint/template used to create containers. It contains your app, dependencies, config, and filesystem layers.

**Q17. What is the difference between an image and a container?**
Image = read-only template (like a class). Container = a running instance of that image (like an object). Many containers can run from one image.

**Q18. How do you pull an image?**
```bash
docker pull nginx
docker pull node:18
docker pull postgres:15
```

**Q19. How do you list all local images?**
```bash
docker images
```

**Q20. How do you remove an image?**
```bash
docker rmi myapp:v1
docker rmi -f myapp:v1    # force remove
```

**Q21. How do you build an image?**
```bash
docker build -t myapp:v1 .
```

**Q22. How do you push an image to Docker Hub?**
```bash
docker tag myapp myusername/myapp:v1
docker login
docker push myusername/myapp:v1
```

**Q23. What is an image tag?**
A version label on an image. Example: `node:18`, `node:18-alpine`, `myapp:v1`. `latest` is the default tag if none is specified.

**Q24. What are image layers?**
Each instruction in a Dockerfile creates a read-only layer. Layers are cached and reused — if nothing changed, Docker uses the cached layer making builds faster.

**Q25. How do you see image layers?**
```bash
docker history myapp:v1
```

**Q26. What is an official image?**
Images maintained by Docker or the software team. They have no username prefix (just `nginx`, not `username/nginx`) and are verified and secure.

**Q27. How do you remove all unused images?**
```bash
docker image prune -a
```

**Q28. What is the image naming convention?**
```
registry/username/image:tag
Example: docker.io/library/nginx:latest
Short:   nginx   (Docker Hub default, latest tag assumed)
```

**Q29. What is a multi-stage build?**
A technique using multiple `FROM` statements in one Dockerfile. Build in one stage (large image), copy only the output to a small final stage. Throws away all build tools.

**Q30. What is a distroless image?**
A distroless image contains ONLY your app and its runtime. No shell, no package manager, no OS utilities. Made by Google. The most secure and smallest option.

## Containers

**Q31. How do you run a container?**
```bash
docker run nginx
docker run -d nginx                  # background
docker run -d --name myapp nginx     # with name
```

**Q32. What does the `-d` flag do?**
Runs the container in detached mode (background). Without it the container runs in the foreground and takes over your terminal.

**Q33. How do you map ports?**
```bash
# Syntax: HOST_PORT:CONTAINER_PORT
docker run -d -p 8080:80 nginx
```

**Q34. How do you pass environment variables?**
```bash
docker run -d -e DB_HOST=localhost myapp
docker run -d --env-file .env myapp
```

**Q35. How do you list running containers?**
```bash
docker ps        # running only
docker ps -a     # all including stopped
```

**Q36. How do you stop a container?**
```bash
docker stop myapp
```

**Q37. How do you remove a container?**
```bash
docker rm myapp
docker rm -f myapp    # force remove a running container
```

**Q38. How do you go inside a running container?**
```bash
docker exec -it myapp bash    # standard
docker exec -it myapp sh      # for Alpine images
```

**Q39. How do you see container logs?**
```bash
docker logs myapp
docker logs -f myapp           # follow live
docker logs --tail 50 myapp    # last 50 lines
```

**Q40. How do you see container resource usage?**
```bash
docker stats              # all containers
docker stats myapp        # specific container
```

**Q41. What is the container lifecycle?**
```
CREATED → RUNNING → STOPPED → REMOVED
docker run → docker stop → docker start → docker rm
```

**Q42. How do you run a one-time command in a container?**
```bash
docker run --rm ubuntu echo hello
# --rm removes the container automatically after it exits
```

**Q43. How do you inspect a container?**
```bash
docker inspect myapp
# Returns full JSON with IP, mounts, env vars, network settings
```

**Q44. How do you see processes inside a container?**
```bash
docker top myapp
```

**Q45. How do you remove all stopped containers?**
```bash
docker container prune    # stopped containers only
docker system prune       # remove everything unused
```

## Dockerfile

**Q46. What is a Dockerfile?**
A plain text file with step-by-step instructions that tells Docker how to build your image — like a recipe for your app.

**Q47. What does `FROM` do?**
Sets the base image. Always the first instruction.
```dockerfile
FROM node:20
FROM python:3.11-slim
FROM alpine:3.18
```

**Q48. What does `WORKDIR` do?**
Sets the working directory for all following instructions. Creates it if it doesn't exist. Like doing `cd /app`.

**Q49. What is the difference between `COPY` and `ADD`?**
`COPY` just copies files from host to image. `ADD` can also extract tar files and download from URLs. Use `COPY` for simple file copies, `ADD` only when you need those extras.

**Q50. What does `RUN` do?**
Executes a command during image **build time** and creates a new layer.
```dockerfile
RUN npm install
RUN apt-get update && apt-get install -y curl
```

**Q51. What does `CMD` do?**
Sets the default command when the container **starts**. Can be overridden at runtime. Only the last `CMD` counts.
```dockerfile
CMD ["node", "app.js"]
```

**Q52. What is the difference between `CMD` and `ENTRYPOINT`?**
`CMD` = default command, can be overridden with `docker run`. `ENTRYPOINT` = fixed command, always runs. Best combo: `ENTRYPOINT` for the executable, `CMD` for default arguments.

**Q53. What does `ENV` do?**
Sets environment variables available during build AND at runtime.
```dockerfile
ENV NODE_ENV=production
ENV PORT=3000
```

**Q54. What is the difference between `ENV` and `ARG`?**
`ENV` is available during build AND when the container runs. `ARG` is only available during build time. Use `ARG` for build-time config, `ENV` for runtime config.

**Q55. What does `EXPOSE` do?**
Documents which port the app listens on. It does **not** actually publish the port — you still need `-p` when running the container.

**Q56. What is `.dockerignore`?**
Like `.gitignore` but for Docker. Tells Docker which files to exclude when copying. Always ignore: `node_modules`, `.git`, `.env`, `*.log`. Makes builds faster and images smaller.

**Q57. Why copy `package.json` before source code?**
Layer caching. `package.json` changes rarely, source code changes often. Copying it first means `npm install` is cached and only reruns if `package.json` changes — not on every code change.

**Q58. How do you reduce image layers?**
Combine `RUN` commands with `&&`:
```dockerfile
RUN apt-get update && \
    apt-get install -y curl && \
    apt-get clean
```

**Q59. What is the builder pattern in Dockerfiles?**
Using a named stage (`AS builder`) to build/compile your app, then copying only the output to a clean final stage. Eliminates build tools from the final image.

**Q60. What is `VOLUME` in a Dockerfile?**
Creates a mount point for persistent data. Signals that this path should be persisted outside the container.
```dockerfile
VOLUME /app/data
```

## Volumes

**Q61. Why do we need volumes?**
Containers are ephemeral — data is lost when removed. Volumes and bind mounts persist data outside the container so it survives restarts and removals.

**Q62. What is a bind mount?**
Mounts a specific folder from your host machine directly into the container. Changes on the host are instantly seen in the container and vice versa.

**Q63. What is a Docker volume?**
A Docker-managed storage area. Docker decides where the data lives (`/var/lib/docker/volumes/`). Persists independently of containers. Best for production data.

**Q64. What is the difference between a bind mount and a volume?**

| | Bind Mount | Volume |
|---|---|---|
| Path control | You choose the path | Docker manages the path |
| Best for | Development (live code) | Production data (databases) |
| Portability | Path-dependent | Portable ✅ |

**Q65. How do you use a bind mount?**
```bash
docker run -v $(pwd):/app myapp
docker run --mount type=bind,source=$(pwd),target=/app myapp
```

**Q66. How do you use a named volume?**
```bash
docker run -v pgdata:/var/lib/postgresql/data postgres
# Docker creates and manages 'pgdata'
# Data survives even if the container is removed ✅
```

**Q67. How do you list all volumes?**
```bash
docker volume ls
```

**Q68. How do you create a volume?**
```bash
docker volume create myvolume
```

**Q69. How do you inspect a volume?**
```bash
docker volume inspect myvolume
# Shows where Docker stores the data on the host
```

**Q70. How do you remove unused volumes?**
```bash
docker volume prune
```

**Q71. What is a read-only bind mount?**
```bash
docker run -v $(pwd)/config:/app/config:ro myapp
# :ro = container can read but cannot write
```

**Q72. When to use bind mount vs volume?**

| Use Case | Storage Type |
|----------|-------------|
| Local development | Bind mount (live code updates) |
| Production app data | Volume |
| Database data | Always volume ✅ |

**Q73. How do you back up a volume?**
```bash
docker run --rm \
  -v pgdata:/data \
  -v $(pwd):/backup \
  alpine \
  tar czf /backup/backup.tar.gz /data
```

**Q74. Can two containers share the same volume?**
Yes. Mount the same named volume in two containers and both see the same files instantly.
```bash
docker run -v shareddata:/data container1
docker run -v shareddata:/data container2
```

**Q75. What is an anonymous volume?**
A volume with no name — Docker generates a random ID. Hard to manage. Use named volumes when possible.
```bash
docker run -v /app/node_modules myapp
```

## Networking

**Q76. What is Docker networking?**
Docker networking allows containers to communicate with each other, with the host machine, and with the outside world.

**Q77. What are the main Docker network types?**

| Driver | Description |
|--------|-------------|
| `bridge` | Default — isolated virtual network |
| `host` | Shares the host machine's network directly |
| `none` | No network — completely isolated |
| `overlay` | Spans multiple hosts — used with Swarm |

**Q78. What is a bridge network?**
The default network driver. Containers connect to a virtual bridge and can communicate via IP. Isolated from the host network.

**Q79. What is the difference between default bridge and custom bridge?**
Default bridge: containers talk by IP only — unreliable since IPs can change. Custom bridge: containers talk by **name** using Docker's built-in DNS. Always use custom bridge for your apps.

**Q80. How do you create a custom network?**
```bash
docker network create mynetwork
docker run --network mynetwork myapp
```

**Q81. How do containers talk to each other by name?**
Docker has a built-in DNS server. On a custom bridge network, container names automatically become hostnames. A container named `api` is reachable as host `api` by any other container on the same network.

**Q82. What is the host network?**
The container shares the host machine's network directly. No port mapping needed but no isolation. Not recommended for production.

**Q83. What is the none network?**
The container has no network at all — completely isolated. Used for batch jobs or maximum security.

**Q84. How do you map ports?**
```bash
# HOST_PORT:CONTAINER_PORT
docker run -p 8080:80 nginx
# Browser hits localhost:8080 → routed to container port 80
```

**Q85. How do you list all networks?**
```bash
docker network ls
```

**Q86. How do you inspect a network?**
```bash
docker network inspect mynetwork
# Shows all connected containers and their IPs
```

**Q87. How do you connect a running container to a network?**
```bash
docker network connect mynetwork mycontainer
```

**Q88. Can containers on different networks talk to each other?**
No. Containers on different networks are isolated by default. You must use `docker network connect` to add a container to the other network.

**Q89. What is the overlay network?**
Connects containers across multiple host machines. Used with Docker Swarm or Kubernetes for distributed applications running on many servers.

**Q90. What is best practice for database networking?**
Never expose the database port to the outside world. Put the DB and API on an internal network only. Only expose the frontend/API ports publicly. Database stays hidden inside.

## Docker Compose

**Q91. What is Docker Compose?**
A tool to define and run multi-container Docker apps using a single `docker-compose.yml` file. One command starts your entire app stack.

**Q92. What is `docker-compose.yml`?**
A YAML file that defines all your services (containers), networks, and volumes in one place. The single source of truth for your entire app infrastructure.

**Q93. How do you start all services?**
```bash
docker compose up -d
# Builds images if needed and starts all containers in the background
```

**Q94. How do you stop all services?**
```bash
docker compose down       # stop and remove containers
docker compose down -v    # also remove volumes
```

**Q95. What does `depends_on` do?**
Controls startup order. `depends_on: postgres` means the service waits for postgres to start. Use with `healthcheck` and `condition: service_healthy` to wait until the service is truly ready.

**Q96. How does Docker Compose handle networking?**
Compose automatically creates a network for your app. All services can reach each other by service name — no manual network setup needed.

**Q97. How do you view logs in Compose?**
```bash
docker compose logs
docker compose logs -f           # follow live
docker compose logs -f api       # specific service
```

**Q98. How do you go inside a Compose service container?**
```bash
docker compose exec api bash    # standard
docker compose exec api sh      # for Alpine
```

**Q99. What are the `restart` policies in Compose?**

| Policy | Behaviour |
|--------|-----------|
| `no` | Never restart (default) |
| `always` | Always restart — use in production |
| `on-failure` | Only restart if the container crashes |
| `unless-stopped` | Restart unless manually stopped |

**Q100. What is `npm ci` vs `npm install` in Docker?**
`npm ci` is strict, fast, never modifies the lock file, and installs exact versions — built for CI/CD and Docker. `npm install` is flexible and can update the lock file — use it for local development only. **Always use `npm ci` in Dockerfiles.**
